# ISO 26262 vocabulary


"The ISO 26262 series of standards is the adaptation of IEC 61508 series of standards to address the sector specific needs of electrical and/or electronic (E/E)
systems within road vehicles. This adaptation applies to all activities during
the safety lifecycle of safety-related systems comprised of electrical, electronic
and software components."

https://www.iso.org/obp/ui/#iso:std:iso:26262:-2:ed-2:v1:en

The ISO 26262 document introduces terminology of ISO 26262.
This includes the definitions of the following classes:

- Element - the common base class of everything. 
- Function - a non-material, abstract 
- Component
- Requirement
- Software
- Processor
- Connector. Connectors model connections between two components in the way that
  they ensure the equality of two quantities.
- Relationship
- Display. A display is a helper-class that just specifies for the use in a front-end
  what to display.
- Feature. A feature is an element that can refer to a number of elements that 
  are not directly owned. The feature specifies
  - multiplicity, an integer range, and
  - the required class, from which the features must be subclasses. 

```SysMD 
package ISO26262 {
    class Element;
    class Function :> Element;
    class Component :> Element; 
    class System :> Component; 
    class Part :> Component; 
    class Software :> Component;
    class Processor :> Component;
    class Comment :> Base::Anything; 
    
    assoc implements :> Links::Link {
      end feature 'from': Component [1..*] redefines source;
      end feature 'to':   Function [1..*] redefines target; 
    }
    
    assoc implementedBy :> Links::Link {
      end feature 'from': Function [1..*] redefines source;
      end feature 'to':   Component [1..*] redefines target; 
    }
    
    assoc executes :> Links::Link {
      end feature 'from': Processor [1..*] redefines source;
      end feature 'to':   Software [1..*] redefines target; 
    } 
    
    assoc executedby :> Links::Link {
      end feature 'from': Component [1..*] redefines source;
      end feature 'to':   Function [1..*] redefines target; 
    }
}
```
We use Element as a base class for all subclasses.
For the analysis of performances we let it have the properties

- Availability: A Boolean value that indicates whether the element is available at a given point in time.
- SecurityOfSupply: A Real value that indicates whether the element -- once it is available -- can be delivered for production. 

The Element class just declares the interface; the concrete function must be given by classes derived from Element.
The following shall apply: 

- An element is _available_ if there exists a valid configuration such that
  - all owned elements are available
  - there exists at least one valuation such that all conditions of properties can be satisfied
  - all requirements of the element and its owned elements are satisfied  

- An element has a _secure supply_ that is > 0 if its availability is true, and its value is
  the product of its owned elements. 

```SysMD
ISO26262::Component hasA 
    attribute Availability: ScalarValues::Boolean(true) = bySubclasses(Availability);
    attribute SecurityOfSupply: ScalarValues::Real(0.0 .. 1.0).
```
